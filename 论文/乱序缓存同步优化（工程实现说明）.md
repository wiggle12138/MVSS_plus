# 乱序缓存同步优化（工程实现说明）

在跨分片账户迁移过程中，`TXsync` 与 `TXmig2` 由不同消息路径传播，真实网络下存在天然乱序：目标分片可能先收到 `TXsync`，后收到用于建立迁移上下文的 `TXmig2`。若接收端在上下文未就绪时直接应用 `TXsync`，会导致状态机推进失败，进而影响后续 `ack` 闭环。为提升系统鲁棒性，工程上采用“先缓存、后应用”的乱序兜底机制：当目标分片检测到 `TXsync` 到达但对应 `MigCtx` 尚未建立时，先将该同步消息按账户地址暂存；待 `TXmig2` 到达并完成 `MigCtx` 初始化后，再触发对暂存 `TXsync` 的串行回放与应用。该机制不改变原有迁移语义，仅在消息到达顺序异常时提供纠偏能力，使同步流程从“顺序依赖”转为“条件依赖”，更符合分布式区块链节点间异步通信的常见运行特征。  

从实现属性看，该方案属于工程增强而非协议重设计：其优势是改动范围小、可快速抑制时序竞争导致的偶发失败；其边界在于当前暂存结构为内存态，尚未引入持久化、重传去重与超时清理等完整协议化保障。因此，该优化可作为迁移同步链路的实用鲁棒性补丁，并为后续协议层完善（如显式 ready 握手、序号幂等校验）提供落地点。
