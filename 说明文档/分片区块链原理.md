# 分片区块链原理（本模拟器视角）

本文档汇总分片链、PBFT 与本仓库 BlockEmulator 仿真的核心概念，供实验与代码阅读对照。细节见 [WORKSPACE_CODE_GUIDE.md](./WORKSPACE_CODE_GUIDE.md)、[账户迁移策略对比.md](./账户迁移策略对比.md)、[实验指标定义.md](./实验指标定义.md)。

---

## 1. 分片区块链

- **分片**：账户按地址哈希映射到各片（`utils.Addr2Shard`：地址后 5 位 hex % 分片数）；片内独立出块、维护状态树。
- **跨片 tx**：发送方片扣款 → **Relay** 到接收方片入账（Monoxide 式中继 + Merkle 证明）。
- **重分片**：客户端跑 CLPA/PageRank 等算法，广播新 `Account2Shard`；迁出账户走 **TXmig1 → TXmig2 → Announce → NS/CaP** 流水线。
- **正常期**：同账户通常只归一片，片内 PBFT 串行执行，nonce 保序，顺序问题较小。
- **迁移期（核心难点）**：同一账户短暂由**源片 + 目标片**并行处理 tx；relay 有延迟 → 可能出现 **old→new→old 时间戳交错**，必须在错误顺序下禁止扣款/nonce 更新。

---

## 2. PBFT 共识

**标准 PBFT**：Leader 打包 → PrePrepare / Prepare / Commit 三阶段 → 各节点**同序** `AddBlock` 执行。

**本模拟器实际热路径**（`pbft/pbftsingle.go`）：

- 实验常只启每片 **N0** → 走 `propose1()` → `commit1()`，**单节点快速出块**。
- 完整 PBFT 代码在 `pbft/pbft.go`，非主实验路径。
- `IsBlockValid()` 恒 `true`；**真正校验**在 `AddBlock` → `getUpdatedTreeOfState` 重算 **StateRoot** 必须与块头一致。

**状态执行**（`chain/blockchain.go`）：从上一块 StateRoot 顺序执行 tx / mig / ann / ns → 更新 MPT → 写回 trie。

## 3. 账户与余额初始化

| 来源 | 内容 |
|------|------|
| CSV | 仅 **from / to / value**；启动前扫地址去重 → `params.Init_addrs`（`test/test_shard.go`，最多 100 万行） |
| 代码 | 统一初始余额 `Init_balance`（极大常数，`params/config.go`） |
| 创世块 | `genesisStateTree`：对每个 `Init_addrs` 写 `Nonce=0, Balance=Init_balance, Location=Addr2Shard` |
| CSV 金额 | 仅作每笔 **tx.Value**；执行时 sender 扣、recipient 加 |

**设计意图**：保证负载重放不因余额不足失败，**不**复现真实链财富分布。

**分片归属**：`Account2Shard`（客户端扫 CSV 或懒加载）；`AccountInOwnShard` 表本片「拥有」账户；迁移后由 TXmig2/Ann 更新。

## 4. 迁移期四策略（保序思路）

| 策略 | 迁移期思路 | RLT | RDT 倾向 |
|------|-----------|-----|----------|
| **SOTA-Lock** | 整账户 + 全部关联交易锁住，迁完再 CaP | 高 | 低* |
| **Fine-tuned-Lock** | 只锁 Payer；Payee 可继续 | 中 | 高 |
| **MVSS** | 按 `RequestTime` vs TXmig1 分老/新 tx；老片/新片分流；交错 → **TXsync** | 低 | 低 |
| **MVSS-Delta** | 同 MVSS 控制面；Stage3 用 **TXsyncDelta** 增量同步 | 低 | 低 |

\*SOTA RDT 低因迁移期**暂停执行**，口径 B 测不到「上链逆序」，非执行层零乱序。

**MVSS 分流规则**：

- `RequestTime ≤ TXmig1` → 老 tx，源片执行  
- `RequestTime > TXmig1` → 新 tx，重定向目标片（RedirectTag + nonce 防重放）  
- `DetectInterleave` 发现 old-new-old → 暂停 + Stage3 状态对齐后再扣款  

**正确性要点**：同账户乱序 = **nonce/余额 bug**；跨账户可并行。扣款发生在 commit 后 `AddBlock` → `getUpdatedTreeOfState`。

---

## 5. 指标：RDT（乱序比例）

- **论文**：发生时间戳交错 / 执行序错误的 TX 数 ÷ TX_reg（按笔数）。
- **口径 B**（`scripts/metrics_definitions.py`）：
  - 逻辑序：`(request_time, txid)`
  - 提交序：`(pbfttime, shard, blockHeight, txid)`
  - 同一 **sender** 下「后发先至」计乱序
- **探针**（Exp2/6）：块高不满足 tx1 < tx2 < tx3 时计入。
- **注意**：Exp1/4 无独立 `ClientTimestamp`，RDT 区分力有限；MVSS 跨片路由可能被口径 B 误判，解读需谨慎。

## 6. 端到端链路（简图）

```text
CSV 扫地址 → 创世赋大余额
     ↓
客户端注入 tx → 各片 N0 打包出块
     ↓
AddBlock：更新状态树、relay、迁移消息
     ↓
客户端算法 → 新映射 → 迁移窗口（四策略差异在此）
     ↓
日志 CSV → Python 指标（Latency / RLT / TPS / RDT / DSR）
```

## 7. 与真实系统的差异（备忘）

- 初始余额统一大数，非 genesis alloc。
- 主路径单节点出块，非完整多副本 PBFT。
- 每片创世块写入**全部** Init_addrs（分片过滤已注释）。
- 研究焦点：**迁移窗口内同账户顺序正确性**，而非复现以太坊经济状态。
