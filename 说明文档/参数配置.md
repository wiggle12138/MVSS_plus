# MVSS+ 参数与实验配置说明（最终版）

本文是 **`params/config.go`** 与 **`params/migration_strategy.go`** 的单一说明文档：字段语义、迁移策略枚举、两类对比实验矩阵及启动方式。**默认值以仓库 `Config = &ChainConfig{ ... }` 字面量为准。**

运行时常由 `test/test_shard.go` 根据命令行覆盖 `NodeID`、`ShardID`、`Shard_num`、`-m MigrationStrategy` 等。

---

## 一、设计原则

| 原则 | 说明 |
|------|------|
| **单一 Config** | 全进程共享 `params.Config`（`*ChainConfig`）。 |
| **策略 1 字段** | 迁移**方法**由 `MigrationStrategy` 表达；`-m` 设置后 **`ApplyMigrationStrategy()`** 同步写入 `Stop/Lock/Not_Lock` 三 bool，业务代码仍读 bool。 |
| **参数独立** | 块大小、注入速率、迁移频率等与策略并列；扫参时只改参数、不改策略。 |
| **扩展场景隔离** | `Fail`、`Cross_Chain`、`Bu_Tong_*` 等为场景修饰，**策略对比实验应全部为 off**。 |

---

## 二、迁移策略（`MigrationStrategy`）

### 2.1 策略一览

| Canonical 名 | 别名（仍可用） | 论文/实验角色 | bool 映射 |
|--------------|----------------|---------------|-----------|
| **`original`** | — | BlockEmulator 工程近似（Not_Lock + CaP） | Not_Lock |
| **`MVSS`** | `MVSS+` | **本文 MVSS 实现**（分流、TX_sync、nonce/RedirectTag） | Not_Lock + `IsMVSS()` |
| **`MVSS-Delta`** | `mvss-delta` | MVSS + 增量 sync（Phase2，最小可行化已接入） | Not_Lock + `IsMVSS()` + `IsMVSSDelta()` |
| **`SOTA-Lock`** | `lock` | **全锁基线**（Fine-tuned Lock 论文 SOTA Lock） | Lock |
| **`Fine-tuned-Lock`** | `finetuned` | **半锁基线**（Huang INFOCOM'24） | Outing_* 半锁 |
| **`stop_epoch`** | — | 停机 epoch 批量迁 | Stop |

### 2.2 基线与论文对应关系（重要）

- **`Fine-tuned-Lock`**：当前代码已实现 `Outing_Acc_Before/After_Announce`、Payer 锁 / Payee 继续执行等，与 Fine-tuned Lock 论文**策略一致**，**可直接 `-m Fine-tuned-Lock` 作对比实验**。
- **`SOTA-Lock`**：当前 `Lock_Acc` + `Locking_TX_Pools`，sender/recipient 关联 tx 全锁，对应 Fine-tuned Lock 论文中的 **SOTA Lock**。
- **不是 LB-Chain**：LB-Chain（Li TPDS'23）使用独立 migration transaction + 队列转发 + 验证推迟，**本仓库未实现**；勿将 `SOTA-Lock` 写成 LB-Chain。

### 2.3 代码入口

```text
IsMVSS()          // MVSS 或 MVSS-Delta
IsMVSSDelta()     // 仅 MVSS-Delta
IsSOTALock()      // SOTA-Lock
IsFineTunedLock() // Fine-tuned-Lock
IsMVSSPlus()      // 过渡期别名，等同 IsMVSS()
```

### 2.4 默认值

| 位置 | 默认策略 |
|------|----------|
| `params/config.go`（未传 `-m`） | **`original`** |
| `start_2shard_2node.bat`（第二参数省略） | **`MVSS`** |

## 三、两类对比实验

### 3.1 维度一：迁移策略对比

**只改 `-m`，其余参数固定。**

```text
Shard_num=2, Block_interval=2, MaxBlockSize=500, Inject_speed=400,
MaxInjectTxs=20000, MigrateBeforeInject=false, Max_Commit_Block=20,
PorC=PageRank, 扩展场景(§五)全部为 off,
数据集=selectedTxs_300K.csv
```

| 运行 | `-m` |
|------|------|
| 本文方法 | `MVSS` 或 `MVSS-Delta` |
| 工程对照 | `original` |
| 全锁基线 | **`SOTA-Lock`** |
| 半锁基线 | **`Fine-tuned-Lock`** |
| 停机迁 | `stop_epoch` |

启动示例：

```bat
start_2shard_2node.bat selectedTxs_300K.csv MVSS
start_2shard_2node.bat selectedTxs_300K.csv Fine-tuned-Lock
start_2shard_2node.bat selectedTxs_300K.csv SOTA-Lock
```

### 3.2 维度二：参数扫参

固定 **`MigrationStrategy=MVSS`**（或 `MVSS-Delta`），只改一列参数，例如：

| 实验 | 字段 | 示例 |
|------|------|------|
| 注入 TPS | `Inject_speed` | 200 / 400 / 800 |
| 负载规模 | `MaxInjectTxs` | 5k / 20k / 全量 |
| 出块间隔 | `Block_interval` | 1 / 2 / 4 |
| 块容量 | `MaxBlockSize` | 300 / 500 / 1000 |
| 迁移频率 | `Max_Commit_Block` | 10 / 20 / 50 |

## 四、`ChainConfig` 字段一览

### 4.1 进程 / 网络（命令行常覆盖）

| 字段 | 说明 |
|------|------|
| **ChainID** | 链标识（默认 77）。 |
| **NodeID** | 本节点 id（`N0` 才 `Propose()` 出块）。 |
| **ShardID** | 本分片（`S0` / `S1`）。 |
| **Shard_num** | 分片总数。 |
| **Malicious_num** | 预留，主流程基本未用。 |
| **Path** | 节点侧 CSV。 |
| **MigrationStrategy** | 迁移策略 enum（见 §二）。 |

网络表 **`NodeTable` / `ClientAddr` / `ShardTable`** 在 `params/config.go` 全局区，见 §4.4。

### 4.2 迁移触发与分区（策略对比中通常固定）

| 字段 | 说明 | 当前默认 |
|------|------|----------|
| **MigrateBeforeInject** | 注入前先重分片并 `SendNewAddr2Shard` | `false` |
| **PorC** | `PageRank` / `CLPA` / `LBF` / `METIS` | `PageRank` |
| **Max_Commit** | 按交易数触发迁移阈值 | `50000` |
| **Max_Commit_Block** | 每分片出块阈值；客户端常 × `Shard_num` | **`20`** |
| **OnlyOnce** | 迁移轮次；`1` 仅一次 | `100` |

### 4.2.1 Sync 探针（MVSS 交错/sync 实验）

| 字段 | 说明 | 默认 |
|------|------|------|
| **EnableSyncProbe** | client 在迁移时注入合成交错交易 | `false` |
| **SyncProbeMaxAccounts** | 每轮最多探针迁出账户数 | `3` |
| **SyncProbeDelayMs** | Phase B 延迟（ms），`0`=2×Block_interval 秒 | `0` |
| **SyncProbeAccount** | 强制指定迁出地址（hex） | 空 |

详见 **`说明文档/Sync探针注入.md`**；client 可加 `--enableSyncProbe`。

### 4.3 区块链与负载（维度二扫参）

| 字段 | 说明 | 当前默认 |
|------|------|----------|
| **Block_interval** | 出块间隔（秒） | **`2`** |
| **MaxBlockSize** | 单块交易容量上界 | **`500`** |
| **MaxMigSize** / **MaxMig1Size** / **MaxMig2Size** | 迁移条数配额 | 300 / 150 / 150 |
| **MaxAnnSize** / **MaxCapSize** | Announce / NS 配额 | 150 / 150 |
| **Relay_interval** | relay 间隔 | 1000 |
| **MaxRelayBlockSize** / **MinRelayBlockSize** | relay 块上下界 | 10 / 1 |
| **Inject_speed** | 客户端每 2s 注入量基准 | **`400`** |
| **MaxInjectTxs** | 客户端最多注入笔数，`0` 不限制 | **`20000`** |
| **ClientSendTX** | 外部客户端注入 | `true` |
| **Not_Lock_immediately** | 简化入队 vs 立即锁 | `true` |
| **RelayLock** | relay 额外锁实验位 | `false` |

### 4.4 由策略推导的 bool（勿与 `-m` 矛盾手动改）

| 策略 | Stop | Lock | Not_Lock |
|------|------|------|----------|
| original / MVSS / MVSS-Delta | false | false | true |
| SOTA-Lock | false | true | false |
| Fine-tuned-Lock | false | false | false |
| stop_epoch | true | false | false |

### 4.5 扩展实验场景（策略对比必须 off）

| 字段 | 说明 |
|------|------|
| **Bu_Tong_Bi_Li** / **Bu_Tong_Bi_Li_2** | 固定地址占比实验 |
| **Bu_Tong_Shi_Jian** / **Bu_Tong_Shi_Jian_Jian_Ge** | 迁移打包时间实验 |
| **Fail** / **Fail_Time** | 模拟迁移失败 |
| **Cross_Chain** | 跨链迁移分支 |
| **Algorithm** / **Pressure** | 算法/压力打包路径 |

## 五、全局变量与辅助函数

| 名字 | 作用 |
|------|------|
| **ClientAddr** | 客户端 TCP（默认 `127.0.0.1:8800`） |
| **NodeTable** | 分片 → 节点 → `ip:port` |
| **ShardTable** / **ShardTableInt2Str** | 分片 id 与整数互转 |
| **Config** | 默认 `ChainConfig` 指针 |
| **Init_addrs** / **Init_balance** | 创世账户与余额 |
| **ActiveShardIDs()** | 按 `Shard_num` 枚举活跃分片 |

## 六、命令行与脚本

```text
go run main.go ... -m MVSS
go run main.go ... -m Fine-tuned-Lock
go run main.go ... -m SOTA-Lock
go run main.go ... --maxInjectTxs 5000   # 客户端快速联调
```

- `params/migration_strategy.go` — 枚举、`ParseMigrationStrategy`、`ApplyMigrationStrategy`
- `test/test_shard.go` — `-m` / `--migrationStrategy`
- `start_2shard_2node.bat` — 第二参数传策略，默认 `MVSS`
