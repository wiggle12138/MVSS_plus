# MVSS 参数配置说明

本文说明 `params/config.go` 中的 **`ChainConfig`**（全局变量 **`Config`** 指向的默认配置）以及同文件内的 **网络表与常量**。运行时常由 `test/test_shard.go` 根据命令行改写 `NodeID`、`ShardID`、`Shard_num`、`Path` 等字段。

**默认值以仓库内 `Config = &ChainConfig{ ... }` 字面量为准**；下文在「当前默认」处列出的是该块中的典型取值（若你本地已改，以代码为准）。

---

## 一、`ChainConfig` 字段一览

| 字段 | 作用说明 |
|------|----------|
| **ChainID** | 链标识号（默认 77）；主仿真路径中几乎不参与共识，多用于测试/占位。 |
| **NodeID** | 当前进程节点 id（如 `N0` / `N1`）。仅 **`N0`** 会启动 `Propose()` 周期性出块。 |
| **ShardID** | 当前进程所属分片（如 `S0` / `S1`），与 **`ShardTable`** 对照得到整数分片号。 |
| **Shard_num** | 总分片数；影响 `Addr2Shard` 取模、客户端按分片桶注入、`ActiveShardIDs()` 枚举等。 |
| **Malicious_num** | 注释为每分片恶意节点上限；命令行传入，**主流程中基本未使用**（保留给 PBFT 恶意模型等扩展）。 |
| **Path** | 节点侧 CSV 路径；`test_shard` 用于读取 `Init_addrs` 等（常与客户端 `-t` 为同一数据集文件）。 |
| **Block_interval** | **出块节拍，单位：秒**。`pbft.Propose()` 中与 **`InitTime`**、**`lastpropose`** 一起决定多久调用一次 `propose1()`。当前默认 **2**。 |
| **MaxBlockSize** | 单块中普通交易与各类迁移相关条目的**总容量上界**（与 `chain.GenerateBlock` 从各池 `Fetch` 的逻辑相关）。当前默认 **500**。 |
| **MaxMigSize** | 迁移类打包的**总配额/预算**（与 `TXmig1` 等池组合，限制单块迁移流量）。当前默认 **300**。 |
| **MaxMig2Size** | `TXmig2_pool` 单块最多打包 **TXmig2**（迁入第二阶段）条数。当前默认 **150**。 |
| **MaxMig1Size** | `TXmig1_pool` 单块最多打包 **TXmig1**（迁出请求）条数。当前默认 **150**。 |
| **MaxAnnSize** | `TXann_pool` 单块最多打包 **Announce** 条数。当前默认 **150**。 |
| **MaxCapSize** | `txnspool`（与 **NS** 类条目相关）单块最多取多少条。当前默认 **150**。 |
| **Relay_interval** | 与中继/relay 打包节奏相关的间隔（默认 **1000**；具体单位以调用处为准，部分路径可能未使用）。 |
| **MaxRelayBlockSize** | 中继块条数上界。当前默认 **10**。 |
| **MinRelayBlockSize** | 中继块条数下界。当前默认 **1**。 |
| **Inject_speed** | 客户端 **`InjectTXS`** 每个周期注入量的基准（与 `2 * inject_speed` 等步长配合）。当前默认 **400**。 |
| **MaxInjectTxs** | **仅客户端**：加载后最多保留/注入前 N 笔；**0 表示不截断**（全量如 300K）。也可用命令行 `--maxInjectTxs` 覆盖。当前仓库默认字面量常为 **0** 或实验用 **5000**，以 `config.go` 为准。 |
| **Max_Commit** | 与「上链多少笔后触发迁移」相关的阈值（客户端等路径仍可见）。当前默认 **50000**。 |
| **Max_Commit_Block** | **每分片**出块计数参与迁移/epoch 等逻辑；客户端中会 **`× Shard_num`**。当前默认 **100**。 |
| **ClientSendTX** | `true`：交易由**外部客户端**注入；`false`：由节点侧其它路径注入（见 `shard/shard.go` 提示）。 |
| **Stop_When_Migrating** | `true`：迁移时停主流程/epoch 等（与 `epochLock`、epoch 变更日志相关）。 |
| **Lock_Acc_When_Migrating** | 迁移时是否**强锁账户**（`Lock_Acc`、`Locking_TX_Pools` 等分支）。 |
| **Not_Lock_Acc_When_Migrating** | 迁移时**不强锁**的另一套策略（`Not_Lock_Acc`、多版本并发实验）。 |
| **Bu_Tong_Bi_Li** | 实验：与**固定地址**相关的「不同交易占比」场景。 |
| **Bu_Tong_Bi_Li_2** | 同上类实验变体（注释涉及多个地址）。 |
| **Bu_Tong_Shi_Jian** | 实验：迁移请求**不同被打包时间**。 |
| **Bu_Tong_Shi_Jian_Jian_Ge** | 与上项配合的间隔/高度参数。 |
| **Fail** | 是否模拟**迁移失败**。 |
| **Fail_Time** | 失败实验触发的**区块高度/时刻**类参数。 |
| **Cross_Chain** | 跨链迁移实验；为真时 **`GenerateBlock`** 拉取普通交易会走特殊分支（与分片 id、Fail 等组合）。 |
| **Algorithm** | 为真时迁移等池走 **`Fetch...2Pack2`** 等「算法/压力」分支。 |
| **Pressure** | 压力测试：一次迁更多账户等（常与 `Algorithm` 一起在 `GenerateBlock` 里切换打包函数）。 |
| **PorC** | 重分片算法名：`PageRank`、`CLPA`、`LBF`、`METIS` 等（`pbft/client.go` 中分支）。 |
| **MigrateBeforeInject** | 是否在**注入交易前**先跑映射并发 `SendNewAddr2Shard`。 |
| **OnlyOnce** | 迁移次数：`1` 表示只迁一次；可设很大表示允许多次。 |
| **Not_Lock_immediately** | `true`：`handleTxFromClient` 走**简化入队**；`false` 则按「立即锁」及子池细分。 |
| **RelayLock** | 与跨片 relay **额外锁**相关的实验位（部分代码已注释，字段保留）。 |

## 二、同文件全局变量（非 `ChainConfig` 字段）

| 名字 | 作用 |
|------|------|
| **ClientAddr** | 客户端 TCP 监听地址；分片主节点 `cReply`、初始时间等会拨号到此。 |
| **NodeTable** | `分片 id → 节点 id → "ip:port"`；各进程 **Listen** 与 **TcpDial** 的目标地址表。 |
| **ShardTable** | 分片字符串到整数（如 `S0→0`，`S1→1`）。 |
| **ShardTableInt2Str** | 整数到分片字符串；**`ActiveShardIDs()`** 按 `Shard_num` 枚举活跃分片时使用。 |
| **Config** | 指向默认 **`ChainConfig`**；`test_shard` 会改其中字段（**指针**，即改全局一份）。 |
| **Init_addrs** | 节点读 CSV 得到的创世账户地址列表（hex 字符串），供 `chain` 建创世状态等。 |
| **Init_balance** | 创世账户初始余额（大整数字符串）。 |

---

## 三、辅助函数

- **`params.ActiveShardIDs()`**：按当前 **`Config.Shard_num`** 返回活跃分片 id 列表（如 2 分片时为 `S0`、`S1`），避免对未启用的 `NodeTable` 分片拨号。

---

## 四、修改建议

- 调**出块快慢**：改 **`Block_interval`**（秒）。  
- 调**单块交易量**：改 **`MaxBlockSize`** 及各 **`MaxMig*Size` / `MaxAnnSize` / `MaxCapSize`**。  
- 联调减轻负载：设 **`MaxInjectTxs`** 为较小正整数，或使用 **`go run ... --maxInjectTxs N`**（见 `test_shard.go`）。
