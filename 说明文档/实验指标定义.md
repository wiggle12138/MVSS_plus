# 实验指标定义

本文档与 `scripts/metrics_definitions.py` **一一对应**：公式以 Python 为准，修改指标时先改 py 再同步本文档。

**原则**：Go 运行时只负责写 CSV；除系统已直接记录的原始量外，**所有派生指标均在 Python 中计算**，便于查阅、复现与批处理。

---

## 1. 数据源

| 文件 | 写入方 | 用途 |
|------|--------|------|
| `S*_block.csv` | 分片 N0 | 块级吞吐、迁移条目、锁池规模、时间戳 |
| `S*_transaction.csv` | 分片 N0 | 单笔延迟、锁标记、迁移时间戳 |
| `S*_queueLen.csv` | 各分片 | 交易池队列长度 |
| `S*_sync.csv` | 分片 N0 | Stage3 同步事件（MVSS / MVSS-Delta） |
| `S*_mig1.csv` | 分片 N0 | 迁出账户与 CommitTime |
| `S*_blockexetime.csv` | 分片 N0 | 单块迁移/公告执行微秒耗时 |
| `migration.csv` | Client | 重分片算法耗时 |

列名以 `pbft/pbft.go`、`pbft/sync_logger.go` 为准。

## 2. 迁移窗口

一次迁移轮次在日志上的时间范围：

```text
w_start = min(blockHeight)  其中 mig1+mig2+ann+ns > 0（跨分片取 min）
w_end   = max(blockHeight)  同上取 max
t_start = timestamp(block w_start)
t_end   = timestamp(block w_end)
t_am    = t_end - t_start   （毫秒）
```

**实现**：`compute_migration_window()`

**用途**：迁移期 TPS、窗口内 RLT、迁移完成时间下限。

## 3. 论文核心指标

### 3.1 Latency（总延迟）

| 项 | 定义 |
|----|------|
| **原始量** | `commit-request` = `CommitTime - RequestTime`（ms），系统已写入 `S*_transaction.csv` |
| **统计** | mean / P50 / P95 / P99 |
| **子集** | 全量；或 `is_migration_related_tx()` 为真的关联交易 |

**实现**：`compute_latency_breakdown()`

### 3.2 Latency 分解 S + L + T（工程近似）

论文：Latency = S（源片排队）+ L（锁等待）+ T（目标片排队）。

本仿真器采用可复现近似（非严格物理分段）：

```text
Total = commit-request

L = max(0, unlock - lock) + max(0, unlock2 - lock2)

S = 若 lock > request：lock - request
    否则若 TXmig1_time > request：TXmig1_time - request
    否则：0

T = max(0, Total - S - L)
```

| 字段 | 含义 |
|------|------|
| `latency_s_mean` | S 的均值 |
| `latency_l_mean` | L 的均值 |
| `latency_t_mean` | T 的均值 |

**注意**：MVSS 无锁时 L≈0；relay 二次到达可参考 `2nd_request_time`（后续版本可细化 T）。

### 3.3 RLT（锁交易比例）

提供三种口径（论文可择一报告，建议主文用 **窗口内 block 级**）：

| 口径 | 公式 | 字段名 |
|------|------|--------|
| Block 级（全局） | Σ`locked_txs` / Σ`tx_total` | `rlt_block_ratio` |
| Block 级（迁移窗口） | 窗口内 locked / tx_total | `rlt_window_ratio` |
| Tx 级 | count(SenLock∨RecLock∨HalfLock) / count(tx) | `rlt_tx_ratio` |

论文原版：RLT = ΣTX_lock / (ΣTX_reg − ΣTX_aux)。仿真器用 block 级 `locked_txs` 近似分子；分母未单独扣除 aux，与 `analyze_logs.locked_ratio` 一致。

**实现**：`compute_rlt()`

### 3.4 TPS（吞吐）

| 口径 | 公式 | 字段名 |
|------|------|--------|
| 迁移期 | Σ`tx_committed`（h∈[w_start,w_end]）/ (t_am/1000) | `tps_migration` |
| 全局 | Σ`tx_committed` / (末块ts−首块ts) | `tps_global` |

**实现**：`compute_tps()`

### 3.5 RDT（乱序比例）

论文：发生时间戳交错 / 执行序错误的 TX 数 / TX_reg（公式 7，按**笔数**）。

**工程判定（口径 B，`compute_rdt()`）**：

1. **范围**：全部迁移关联交易（`is_migration_related_tx`，含锁标记或 mig1/mig2 非零）。
2. **逻辑序**：`(request_time, txid)`（注入时刻；同毫秒用 txid 打破平局）。
3. **全局提交序**：`(pbfttime, shard_idx, blockHeight, txid)`，其中 `pbfttime` 来自各分片 `S*_block.csv`。
4. **乱序 tx**：同一 `sender` 下，若存在 `i` 逻辑先于 `j`，但 `j` 提交更早（后发先至），则 `j` 计入分子。
5. **探针**（Exp2/6）：块高不满足 `block(tx1) < block(tx2) < block(tx3)` 时，该组探针 tx 计入分子。

```text
RDT = disordered_tx_count / tx_reg_count
```

| 字段 | 含义 |
|------|------|
| `rdt_ratio` | 乱序交易比例 |
| `rdt_disordered_count` | 乱序交易笔数 |
| `rdt_sample_count` | TX_reg 总笔数（分母） |

**预期**：MVSS / MVSS-Delta 低于锁基线；关探针主实验（Exp1/4）下 MVSS 系应明显低于 SOTA-Lock。

### 3.6 DSR（Delta Sync Ratio，期刊增量）

论文：DSR = Size_delta / Size_full × 100%。

| 场景 | 计算 |
|------|------|
| 同 run 含 sync+delta 的 send | `send_bytes_delta / send_bytes_sync` |
| 仅 delta（常见） | `send_bytes_delta / (delta账户数 × 128)`；delta 账户数从 `reason=batch=N` 累加，若无 batch 则用 `apply` 计数 |

**说明**：batch send 时 `send` 行 `addr` 为空，旧版脚本误用分母 `1×128` 会导致 DSR 虚高（~90+）；修复后请对归档 `raw/` 重新跑 `metrics_definitions.py` 再对比。

| 字段 | 含义 |
|------|------|
| `dsr` | 比值（0~1，报告时可 ×100%） |
| `sync_bandwidth_mb` | Σsend.bytes / 10⁶ |
| `sync_send_count` | event=send 条数 |

**实现**：`compute_sync_metrics()`

## 4. 同步与探针（正确性 + 实验二）

### 4.1 Sync 指标

来自 `S*_sync.csv`（`ts,event,mode,addr,start_n,end_n,ok,reason,bytes`）：

| 指标 | 计算 |
|------|------|
| 消息数 | count(event=send/recv/apply/ack_send/ack_recv/abort) |
| 带宽 MB | Σbytes（send 方向）/ 10⁶ |
| Sync 延迟 | 同分片内：`ack_recv.ts − send.ts`；**batch send**（`addr` 为空）时各 `ack_recv` 相对**最近一次 send** |
| batch 规模 | 从 `reason=batch=N` 解析；输出 `batch_send_count`、`batch_size_mean/max` |
| 同步延迟占比 | mean(sync延迟) / t_am |

**时间戳量纲**：`sync.csv` 的 `ts` 与 `block.csv` 的 `pbfttime` 均为 **Unix ms**；`block.timestamp` 为相对 ms，**不可**与 `sync.ts` 直接相减。

### 4.1.1 Exp6 专用 Stage3 指标（`metrics_definitions.py` → `exp6`）

| 字段 | 含义 |
|------|------|
| `stage3_makespan_ms` | 首 send → 末 ack_recv |
| `send_to_first_ack_ms` / `send_to_last_ack_ms` | send 到首/末 ack_recv |
| `sync_per_ack_latency_median_ms` / `_p95_ms` | 逐 ack 相对 send 延迟 |
| `probe_tx1_to_tx3_span_median_ms` / `_p95_ms` | 探针 tx1 与 tx3 上块 pbfttime 差 |
| `delta_account_count_est` | batch 或 apply 估计的 delta 账户数 |

扁平 JSON 键名带 `exp6_` 前缀（如 `exp6_stage3_makespan_ms`）。详见 `说明文档/实验文档/exp6_窗口敏感性实验.md`。

### 4.2 探针正确性（`EnableSyncProbe`）

| 指标 | 判定 |
|------|------|
| `probe_tx_count` | 探针 Id 上链条数 |
| `block_order_ok` | 每账户 tx1/2/3 块序正确 |
| `sync_pipeline_ok` | send→apply→ack_recv 存在且无 abort,delta |
| `probe_ok` | 以上两者且 |

详细报告仍用 `scripts/analyze_sync_probe.py`；`metrics_definitions` 内为轻量验收。

### 4.3 迁移完成时间

```text
migration_completion_ms =
  若有 sync 事件：max(sync.ts) - migration_window.t_start_pbft_ms
  （sync.ts 与 pbfttime 均为 Unix ms；勿用 block.timestamp）
  否则：t_am（迁移窗口相对时长）
```

可选辅助：`exp6.stage3_makespan_ms` = 首 send → 末 ack_recv（仅 Stage3 段，不含 mig1 之前）。

实验二「准备/同步/广播」分解可在批处理脚本中组合：

- 准备：`mig1` 首块 → `mig2` 末块（`blockexetime` / block 时间戳）
- 同步：首条 send → 末条 ack_recv
- 广播：announce 段（`ann` > 0 的块区间）

## 6. 六大实验与指标映射

| 实验 | 主要指标 | 数据来源 | 批处理难度 |
|------|----------|----------|------------|
| **一、可扩展性** | Latency, RLT, TPS, RDT | block + transaction | **低**：扫参数 + 调现有 py |
| **二、高并发迁移** | 迁移完成时间, sync 带宽/消息数, DSR, MVSS vs Delta | sync + mig + 探针 | **低**：已有探针与 sync 日志 |
| **三、安全攻击** | 攻击成功率, 防御延迟 | — | **高**：需攻击注入器，暂无 |
| **四、以太坊负载** | 延迟 CDF, RDT/DSR 按类型 | transaction + 数据集类型列 | **中**：缺类型标注时需扩 CSV |
| **五、资源开销** | CPU/内存 | — | **高**：需 pprof/perf，暂无 |
| **六、参数敏感性** | DSR, sync 延迟 vs `DeltaAggregateWindowMs` | sync + config | **低**：改 config 扫参 |

## 8. 使用方式

```bat
REM 单次 run 输出 JSON
python scripts/metrics_definitions.py --log-dir log --out results/current_run/metrics.json

REM 在其它脚本中引用
python -c "from pathlib import Path; from metrics_definitions import analyze_run, run_metrics_to_dict; print(run_metrics_to_dict(analyze_run(Path('log'))))"
```

（在 `scripts/` 目录下执行，或保证 `PYTHONPATH` 含 `scripts`。）

## 9. 六大批处理脚本规划（本轮不实现）

建议 **每个实验一个入口脚本**，共用 `metrics_definitions.py`：

```text
scripts/
  metrics_definitions.py      # 指标公式（本文档）
  run_exp1_scaling.py         # 实验一：分片数 × TPS 矩阵
  run_exp2_migration_stress.py # 实验二：并发账户 × MVSS/Delta + 探针
  run_exp3_security.py        # 实验三：待攻击模块
  run_exp4_eth_workload.py    # 实验四：数据集回放
  run_exp5_profiling.py       # 实验五：对接 pprof
  run_exp6_sensitivity.py     # 实验六：DeltaAggregateWindowMs 扫描
```

**Windows**：可继续用 `.bat` 调 `go run` + `python`。  
**Linux Docker**：同一套 py，仅将「启节点 / 等就绪 / 归档 log」换成容器编排；指标层无需重写。

### 实现难度评估

| 脚本 | 难度 | 说明 |
|------|------|------|
| exp2 + 探针 | ★☆☆ | 现有 `start_2shard_2node_log.bat` + 探针 + `metrics_definitions` 即可闭环 |
| exp6 敏感性 | ★☆☆ | 改 `DeltaAggregateWindowMs` 循环跑 |
| exp1 可扩展性 | ★★☆ | 需扩 `NodeTable` 分片数、统一启停；2→4 分片先验证 |
| exp4 以太坊负载 | ★★☆ | 数据集与注入区间管理 |
| exp3 安全 | ★★★ | 新功能 |
| exp5 性能剖析 | ★★★ | 新设施 + 与仿真器集成 |

整体：**6 个脚本架构合理、不困难**；难在 exp3/exp5 的前置能力，而非脚本本身。建议先做 exp2 → exp6 → exp1，exp3/exp5 并行补基础设施。
