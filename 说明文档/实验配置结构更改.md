# 实验配置结构更改说明

本文定义 **全局唯一 `params.Config`** 的配置组织方式，用于：

1. **MVSS+**（新方法，逐步实现）与 **MVSS / 基线 / 扩展实验** 在配置层分离；
2. 支撑两类对比实验：**策略对比**（维度一）与 **参数扫参**（维度二）。

**后续代码修改以本文为准。** 当前阶段仅梳理结构，业务逻辑仍读现有 bool，待实现「策略枚举 → bool 映射」后再逐步收敛。

---

## 一、设计原则

| 原则 | 说明 |
|------|------|
| **单一 Config** | 全进程共享 `params.Config`（`*ChainConfig`），不拆多个全局 Config 文件。 |
| **策略用 1 个字段** | 账户迁移**方法**由 `MigrationStrategy` 枚举表达，替代 `Lock / Not_Lock / Stop` 等多 bool 组合。 |
| **参数独立字段** | 块大小、注入速率、迁移触发频率等作为 **运行参数**，与策略字段并列，扫参时只改参数、不改策略。 |
| **扩展场景单独标记** | `Fail`、`Cross_Chain`、`Bu_Tong_*` 等视为 **场景修饰**，不属于「迁移策略」本身；策略对比实验中应全部为 false/默认。 |
| **向后兼容（过渡期）** | 实现 `ApplyMigrationStrategy()`：设置 enum 后 **同步写入** 现有 bool，旧代码无需一次改完。 |

---

## 二、两类对比实验

### 2.1 维度一：迁移策略对比

**目的**：在相同负载与链参数下，比较不同账户迁移方法。

| 固定项（示例） | 变化项 |
|----------------|--------|
| `Shard_num`、数据集、`Block_interval`、`MaxBlockSize` | **`MigrationStrategy` 仅此一项** |
| `Inject_speed`、`MaxInjectTxs` | |
| `MigrateBeforeInject`、`PorC`（若策略对比不含「注入前分区算法」则一并固定） | |
| 扩展场景开关全部为 off | |

**典型对比组**（与 `说明文档/实验扩展.md` 一致）：

| `MigrationStrategy` | 含义 | 实验角色 |
|---------------------|------|----------|
| **`MVSS+`** | 新方法接口（分流 + TX_sync + 安全等，**待实现**） | **本文提出方法** |
| **`MVSS`** | 论文 MVSS 对齐目标；**当前暂用现有工程逻辑**（Not_Lock + CaP） | 论文复现 / 过渡 |
| `lock` | 迁移期全锁账户 | 基线 |
| `finetuned` | 半锁 | 基线 Fine-tuned |
| `stop_epoch` | 停机 epoch 批量迁 | 基线 Stop-and-migrate |

### 2.2 维度二：参数扫参（固定论文策略）

**目的**：在 **已选定的 `MigrationStrategy`（通常为 `MVSS+` 或实现完成后的主方法）** 下，观察性能随参数变化。

| 固定项 | 变化项（示例） |
|--------|----------------|
| **`MigrationStrategy = MVSS+`**（或扫参阶段暂固定 `MVSS`） | `Inject_speed` |
| 扩展场景 off | `MaxInjectTxs` / 数据集规模 |
| | `Block_interval` |
| | `MaxBlockSize`、各 `MaxMig*Size` |
| | `Max_Commit_Block`（迁移触发频率，× 分片数在客户端使用） |
| | `OnlyOnce`（允许多次迁移 vs 一次） |
| | `Shard_num`（可扩展性实验，见实验扩展 §1） |

## 三、目标 `ChainConfig` 结构（改后）

仍保留 **一个** `ChainConfig`，字段按职责分为四组（注释分区即可，不必拆文件）。

### 3.1 进程 / 网络（命令行常覆盖）

| 字段 | 说明 |
|------|------|
| `ChainID` | 链 ID |
| `NodeID` / `ShardID` | 本进程节点与分片 |
| `Shard_num` | 分片总数 |
| `Malicious_num` | 预留 |
| `Path` | 节点侧 CSV（创世账户等） |

网络表 **`NodeTable` / `ClientAddr`** 仍在 `params/config.go` 全局变量区，不属于 `ChainConfig` 扫参范围（环境相关）。

### 3.2 迁移策略（维度一核心：1 个字段）

```go
// MigrationStrategy 账户迁移方法（互斥，一次运行仅一种）
type MigrationStrategy string

const (
    StrategyMVSSPlus MigrationStrategy = "MVSS+"  // 新方法（逐步实现）
    StrategyMVSS     MigrationStrategy = "MVSS"   // 论文 MVSS；当前走现有逻辑
    StrategyLock         MigrationStrategy = "lock"
    StrategyFinetuned    MigrationStrategy = "finetuned"
    StrategyStopEpoch    MigrationStrategy = "stop_epoch"
)
```

| 字段 | 类型 | 默认值 |
|------|------|--------|
| **`MigrationStrategy`** | `MigrationStrategy` | **`MVSS`**（联调默认；与现有可跑通逻辑一致） |

> `Not_Lock_immediately`、`RelayLock` 等为**既有扩展/细粒度实验字段**，不属于迁移策略 enum；策略对比时保持 `config.go` 默认值即可，本文档不单独列出。

### 3.3 迁移触发与分区（策略对比中通常固定，扩展实验可扫）

| 字段 | 说明 | 默认 |
|------|------|------|
| `MigrateBeforeInject` | 注入前是否先重分片并 `SendNewAddr2Shard` | `false` |
| `PorC` | 重分片算法：`PageRank` / `CLPA` / `LBF` / `METIS` | `PageRank` |
| `Max_Commit` | 按交易数触发迁移的阈值（部分路径仍引用） | `50000` |
| `Max_Commit_Block` | **每分片**出块数阈值；客户端侧常 × `Shard_num` | `20`（以 `config.go` 为准） |
| `OnlyOnce` | 迁移轮次：`1` 仅一次，大值允许多轮 | `100` |

### 3.4 区块链与负载参数（维度二扫参）

| 字段 | 说明 | 默认 |
|------|------|------|
| `Block_interval` | 出块间隔（秒） | `2` |
| `MaxBlockSize` | 单块交易容量上界 | `500` |
| `MaxMigSize` / `MaxMig1Size` / `MaxMig2Size` / `MaxAnnSize` / `MaxCapSize` | 迁移类条目的块内配额 | 300 / 150 / … |
| `Relay_interval` / `MaxRelayBlockSize` / `MinRelayBlockSize` | relay 相关 | 1000 / 10 / 1 |
| `Inject_speed` | 客户端每周期注入量基准 | `400` |
| `MaxInjectTxs` | 客户端最多注入笔数，`0` 不限制 | `20000`（以代码为准） |
| `ClientSendTX` | 是否外部客户端注入 | `true` |

### 3.5 扩展实验场景（策略对比中必须全部为 off）

不属于「迁移策略」；仅在专门扩展实验开启。**不得**与策略 enum 混为一谈。

| 字段 | 说明 | 策略对比默认 |
|------|------|--------------|
| `Bu_Tong_Bi_Li` / `Bu_Tong_Bi_Li_2` | 固定地址交易占比实验 | `false` |
| `Bu_Tong_Shi_Jian` / `Bu_Tong_Shi_Jian_Jian_Ge` | 迁移打包时间实验 | `false` / 忽略 |
| `Fail` / `Fail_Time` | 模拟迁移失败 | `false` |
| `Cross_Chain` | 跨链迁移分支 | `false` |
| `Algorithm` / `Pressure` | 打包算法/压力路径 | `false` |

## 四、`MigrationStrategy` → 现有 bool 映射（过渡期）

实现 **`ApplyMigrationStrategy(cfg *ChainConfig)`**（或设置 `MigrationStrategy` 时自动调用），将 enum **推导** 为现有三个主 bool，供未重构代码继续使用：

| `MigrationStrategy` | `Stop_When_Migrating` | `Lock_Acc_When_Migrating` | `Not_Lock_Acc_When_Migrating` | 说明 |
|---------------------|------------------------|---------------------------|-------------------------------|------|
| `MVSS+` | `false` | `false` | `true` | 与 MVSS 相同 bool；**新逻辑仅在 `StrategyMVSSPlus` 分支启用** |
| `MVSS` | `false` | `false` | `true` | 现有工程路径（`Not_Locking_TX_Pools`、`cCaP`） |
| `lock` | `false` | `true` | `false` | `Locking_TX_Pools` |
| `finetuned` | `false` | `false` | `false` | `Outing_*` 半锁池 |
| `stop_epoch` | `true` | `false` | `false` | `PBFTforMigrate.go` |

**校验规则（启动时）**：

- `MigrationStrategy` 必须为上述五者之一；
- 策略对比实验：扩展场景字段（§3.5）全部为 false；
- 禁止手动把三个主 bool 设成与 `MigrationStrategy` 矛盾的值（过渡期：以 enum 为准，bool 只读或每次 Apply 覆盖）。

### 4.1 当前仓库默认 ↔ 策略名

当前 `config.go` 字面量：

```text
Stop=false, Lock=false, Not_Lock=true  →  MigrationStrategy = MVSS（默认）
```

`start_2shard_2node.bat` 默认 **`-m MVSS`**；开发 MVSS+ 时使用第二参数 **`MVSS+`**。

## 五、实验配置示例

### 5.1 策略对比（维度一）

除 `MigrationStrategy` 外，以下全部相同：

```text
Shard_num=2, Block_interval=2, MaxBlockSize=500, Inject_speed=400,
MaxInjectTxs=5000, MigrateBeforeInject=false, Max_Commit_Block=20,
数据集=selectedTxs_300K.csv
```

| 运行 | `MigrationStrategy` |
|------|---------------------|
| A 新方法（目标） | `MVSS+` |
| B 论文 MVSS（当前=现有逻辑） | `MVSS` |
| C 全锁基线 | `lock` |
| D 半锁基线 | `finetuned` |
| E 停机迁 | `stop_epoch` |

### 5.2 参数扫参（维度二）

固定 `MigrationStrategy=MVSS+`（实现前扫参可暂用 `MVSS`），只改一列：

| 实验 | 变更字段 | 取值示例 |
|------|----------|----------|
| 注入 TPS | `Inject_speed` | 200 / 400 / 800 |
| 负载规模 | `MaxInjectTxs` | 5k / 20k / 全量 |
| 出块间隔 | `Block_interval` | 1 / 2 / 4 |
| 块容量 | `MaxBlockSize` | 300 / 500 / 1000 |
| 迁移频率 | `Max_Commit_Block` | 10 / 20 / 50 |

## 六、与论文主线的关系

| 策略 | 定位 |
|------|------|
| **`MVSS+`** | 本文新方法；代码在 `cfg.MigrationStrategy == StrategyMVSSPlus` 下逐步实现 TX_sync 等。 |
| **`MVSS`** | 论文 MVSS 对齐接口；**当前**与现有 Not_Lock 逻辑相同，论文机制补全后在此策略完善。 |
| **`lock` / `finetuned` / `stop_epoch`** | 对比基线。 |

`MVSS+` 与 `MVSS` 在 TX_sync 未分叉前 **bool 映射相同**；业务代码通过 `StrategyMVSSPlus` / `StrategyMVSS` 区分。

## 七、代码修改计划（按本文实施）

### Phase 0（文档，已完成）

- 本文 + 与 `参数配置.md`、`代码论文区别.md` 交叉引用。

### Phase 1（配置层，不改业务分支）— **已完成**

1. `ChainConfig.MigrationStrategy` + `params/migration_strategy.go`（常量、`ApplyMigrationStrategy`、`ParseMigrationStrategy`）。

- 在 `StrategyMVSSPlus` 分支实现 TX_sync、分流、安全字段；`StrategyMVSS` 逐步对齐论文；基线策略冻结。

### Phase 3（实验脚本）

- bat / 脚本：维度一只改 `-m`；维度二固定 `-m MVSS+` 扫参。

## 九、小结

- **一个全局 Config** 即可；**迁移方法 = 1 个 `MigrationStrategy` 字段**。
- **维度一**只改策略；**维度二**固定策略、改 §3.4 参数。
- **扩展场景**（§3.5）不参与策略 enum，策略对比时关闭。
- 代码改动从 **Phase 1（enum + Apply + 可选 CLI）** 开始，业务逻辑仍用 bool，风险最小。

*文档版本：与仓库 `params/config.go` 默认（Not_Lock=true）对齐；若默认字面量变更，请同步更新 §4.1。*
