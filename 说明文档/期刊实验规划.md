# 期刊实验规划

本文说明 Mary 初版六大实验（见 [`MVSS+修改——Mary.txt`](./MVSS+修改——Mary.txt)）在本仓库 **Sync 探针方案** 下如何落地。实验指标见 [实验指标定义.md](./实验指标定义.md)；探针设计与论文表述见 [Sync探针注入.md](./Sync探针注入.md) §12。

---

## 一、两层实验分工

| 层次 | 探针 | 对比策略 | 主要指标 |
|------|------|----------|----------|
| **主实验** | **关** `EnableSyncProbe` | SOTA-Lock / Fine-tuned-Lock / MVSS / MVSS-Delta | Latency、RLT、TPS、RDT |
| **Stage3 微基准** | **开** 探针 | MVSS vs MVSS-Delta | DSR、sync 消息数/字节、`S*_sync.csv` |

关闭探针时，默认 `selectedTxs_300K.csv` 无独立 ClientTS，**几乎不会自然触发 Stage3**（见探针文档 §12.3）。因此：**整体性能走主实验；交错同步与 Delta 带宽走探针微基准**，二者互补，不互相替代。

---

## 二、六大实验（探针方案下）

### 实验一：可扩展性（Scaling）

**目标**：分片数、注入速率、迁移比例增长时 MVSS 系相对锁基线的优势是否保持。

| 项 | 设定 |
|----|------|
| 探针 | **关** |
| 策略 | 四组：SOTA-Lock / Fine-tuned-Lock / MVSS / MVSS-Delta |
| 参数 | `Shard_num` 4→64；`Inject_speed` 200→4000；迁移比例由 CLPA + 数据集控制 |
| 数据 | `selectedTxs_300K.csv` 或 XBlock 子集 |
| 指标 | Latency、RLT、TPS、RDT |
| 脚本 | `scripts/metrics_definitions.py`；待补 `run_exp1_scaling` |

**注意**：64 分片 × 128 节点单机不可行；先做 2→4→8 分片验证脚本与日志完整性。

---

### 实验二：高并发迁移压力（MVSS vs MVSS-Delta）

**目标**：多账户同时迁移时，增量 sync 相对全量 sync 的带宽与消息开销。

| 项 | 设定 |
|----|------|
| 探针 | **开**（每轮迁移构造 old→new→old） |
| 策略 | **仅** MVSS vs MVSS-Delta |
| 参数 | 并发迁移账户 10→500；`Shard_num=16`，`Inject_speed=2000`；`SyncProbeMaxAccounts` 与并发数对齐 |
| 指标 | 迁移完成时间、sync 总字节、TXsync/Delta 消息数、DSR；`analyze_sync_probe.py` |
| 脚本 | 现有 `start_2shard_2node_log.bat` + `-m MVSS` / `MVSS-Delta` + `SYNC_PROBE=1` |

**优先级**：★ 最先跑通（探针 + sync 日志已具备）。

---

### 实验三：安全攻击防御（双花 / 重放）

**目标**：nonce + RedirectTag 防御有效性与额外开销。

| 项 | 设定 |
|----|------|
| 探针 | **关**（攻击与 Stage3 正交） |
| 策略 | MVSS / MVSS-Delta |
| 实现 | **待开发**：client 攻击注入模式、成功率与验证耗时日志 |
| 指标 | 攻击成功率、防御额外延迟、nonce 验证 CPU 时间 |

**优先级**：★★★ 需新设施；与 exp2/exp6 可并行规划接口。

---

### 实验四：真实以太坊负载

**目标**：历史链上交互模式下的延迟与 RDT。

| 项 | 设定 |
|----|------|
| 探针 | **关** |
| 策略 | 四组全对比 |
| 数据 | XBlock 子集（如 20 万–50 万笔）；区块 timestamp 作粗粒度顺序，**不用于 Stage3 验收** |
| 指标 | P50/P95/P99 Latency、RDT（按类型分组需扩展 CSV 解析） |
| 脚本 | `metrics_definitions.py`；交易类型统计待补 |

---

### 实验五：资源开销细粒度分析

**目标**：同步阶段 CPU / 内存 / 网络实际开销。

| 项 | 设定 |
|----|------|
| 探针 | **开**（固定 Stage3 负载，便于对比 sync 阶段） |
| 策略 | MVSS vs MVSS-Delta |
| 实现 | **待开发**：pprof、`runtime.ReadMemStats`、TCP 字节计数 |
| 指标 | sync 阶段 CPU 占比、每账户内存增量、消息大小 CDF（可结合 `S*_sync.csv` 的 `bytes`） |

---

### 实验六：参数敏感性（聚合窗口）

**目标**：`DeltaAggregateWindowMs` 对带宽与迁移延迟的权衡。

| 项 | 设定 |
|----|------|
| 探针 | **开** |
| 策略 | **仅** MVSS-Delta |
| 参数 | `DeltaAggregateWindowMs ∈ {0, 50, 100, 200, 500}`（见 [聚合窗口.md](./聚合窗口.md)） |
| 指标 | send 条数、`bytes`、sync 延迟、abort 率；`sync.csv` 中 `reason=batch=N` |
| 脚本 | 循环改 config / 环境变量后跑探针批处理 |

**说明**：论文中的滑动窗口 W（OrderList 侧）**尚未完整实现**；本实验先扫 **出站 delta 聚合窗口**（已实现 MVP）。

## 三、建议实施顺序

```text
exp2（探针 + MVSS vs Delta）
  → exp6（DeltaAggregateWindowMs）
  → exp1（关探针四策略扩展）
  → exp4（XBlock 主实验）
  → exp3 / exp5（补攻击与 profiling 设施）
```

批处理：六个实验各一脚本，共用 `scripts/metrics_definitions.py` 与 `scripts/analyze_sync_probe.py`（待补 `run_exp*.py`）。
