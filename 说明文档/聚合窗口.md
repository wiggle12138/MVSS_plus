# MVSS-Delta 出站 Delta 聚合与窗口

本文说明 **源片 State_ini delta 出站聚合** 的当前实现、日志验收方式，以及与论文设计的差距与可优化方向。

**前置阅读**：[`Sync探针注入.md`](./Sync探针注入.md)（探针故事线、Stage3 验收）。  
**代码位置**：`pbft/mvss_delta.go`、`pbft/mvss_sync.go`、`params/config.go`。

---

## 1. 背景：论文 vs 当前实现

论文 MVSS-Delta Stage3 提出：在滑动窗口内 **聚合多次账户状态增量**，减少跨片 sync 消息数量与带宽；并可配合 π_delta 等证明增强校验。

**当前 MVP 已实现**：

- 源片在 prefix-old 提交就绪后，为每个账户构造 **State_ini delta**（∆balance、∆nonce、`[StartN, EndN)`、PrevHash 链）
- 多条 delta 在 **发送层** 合并为一条 `SyncDeltaMsg`，一次 TCP 发往目标片
- 目标片 **仍逐账户 apply**；**Ack 仍逐账户单条发送**

**尚未实现**：Ack 方向聚合、自适应窗口、π_delta Merkle 证明、StorageRoot、多轮 sync / R-shard 等。

---

## 2. 聚合范围（什么合并、什么不合并）

| 方向 | 消息类型 | 当前行为 |
|------|----------|----------|
| 源片 → 目标片 | State_ini delta（`Ack=false`） | **可聚合**（同目标分片、同批次） |
| 目标片 → 源片 | delta ack（`Ack=true`） | **不聚合**，每账户 new 上链后单独 `TrySendTXsyncDelta` |

语义上：交错检测与 delta 内容仍 **按账户** 在 `MigCtx` / `mvssSendSyncForAddr` 中生成；聚合只减少 **网络报文条数**，不改变 apply/ack 的 per-account 逻辑。

---

## 3. 实现机制

### 3.1 数据流

```text
mvssOnBlockCommitted
  └─ 对每个源片账户：prefix-old 就绪
       └─ mvssSendSyncForAddr → enqueueOutboundStateIniDelta（入队，不立刻 TCP）
  └─ 块末：mvssFlushAllOutboundStateIniAtBlockEnd
       └─ mvssFlushOutboundStateIniDeltas（按目标分片）
            └─ TrySendTXsyncDelta([]*TXsyncDelta{...})  // 一条 SyncDeltaMsg

目标片 handleTXsyncDelta
  └─ for each delta in msg：apply / pending / ack 分支
```

### 3.2 队列与去重

- 全局 map：`outboundStateIniByTarget[targetShardID][]*TXsyncDelta`
- 同一 `(Address, StartN, EndN)` 重复入队会被忽略
- `cloneTXsyncDelta` 避免块内状态被后续修改污染

### 3.3 两种 flush 模式（`DeltaAggregateWindowMs`）

| 值 | 行为 | 延迟影响 |
|----|------|----------|
| **0**（默认） | 仅在 **块提交末尾** force flush；同块内多账户 → 一条 batch | **不额外增加** sync 延迟 |
| **>0** | 批次首条 delta 入队时启动 `time.AfterFunc(window)`；到期 flush；块末仅在 window=0 时 force | **可能跨块等待**，主动增加聚合粒度 |

设计意图：

- **window=0**：块边界 batch，适合探针与常规迁移（多账户同块 prefix-old 就绪时 `batch=N`）
- **window>0**：模拟论文「时间窗口内聚合」，用于带宽/消息数实验；需接受 sync 延后

## 4. 参数

| 字段 | 默认 | 说明 |
|------|------|------|
| `DeltaAggregateWindowMs` | `0` | 源片 State_ini 出站聚合窗口（毫秒） |

配置于 `params/config.go`；当前无 CLI flag，改默认值或运行时赋值即可。

## 5. Sync 发送与处理时机（与探针块序）

以探针 3 账户、块 22 发送为例：

| 阶段 | 事件 |
|------|------|
| 块 22 commit | 三账户 prefix-old 就绪 → 入队 → **块末** 一条 `send,delta`（`batch=3`） |
| 块 23 前后 | S1 `recv` → 逐条 `apply`（若早于 TXmig2 则 pending，mig2 块后 flush） |
| Phase B 后 | tx2 入 S1 池 → promote nonce → 某块执行 → `ack_send` ×3 |
| ack 后 | S0 `ack_recv` → Resume tx3 |

**22 块 send 与 25 块 tx2 之间的间隔** 主要来自：

1. 探针 **Phase B 故意延迟**（默认 3×`Block_interval` ≈ 6s）
2. 出块间隔与 S1 长队列排队

这与 delta **聚合** 无关；`window=0` 不会在 send 上再加等待。

## 6. 日志验收

### 6.1 通过样例（3 探针账户，window=0）

**`log/S0_sync.csv`**

```text
send,delta  reason=batch=3
ack_recv,delta ×3（各 addr）
```

**`log/S1_sync.csv`**

```text
recv,delta  reason=batch=3
apply,delta ×3
ack_send,delta ×3
```

终端可见：`[MVSS-Delta] S0 聚合 flush State_ini delta → 目标片 1，条数=3`。

### 6.2 与未聚合对比

| 指标 | 未聚合 | 聚合（window=0） |
|------|--------|------------------|
| S0 `send` 行数 | N（每账户 1） | 1（`batch=N`） |
| S1 `recv` 行数 | N | 1 |
| `apply` / `ack_*` | 各 N | 各 N（不变） |
| Stage3 语义 | 相同 | 相同 |

## 7. 与论文完整设计的差距

| 论文能力 | 当前 |
|----------|------|
| 窗口内聚合小 delta | ✅ 传输层 batch（块末或定时 window） |
| 自适应窗口（负载/带宽） | ❌ 固定 `DeltaAggregateWindowMs` |
| π_delta 状态证明 | ❌ 仅 PrevHash / EndN 链式校验 |
| Ack 批量回传 | ❌ 单笔 ack |
| 多轮增量 sync | ❌ 单轮 State_ini + ack 闭环 |

扩展账户数或乱序交易数时：**无需改探针逻辑**；只要同块（或同 window）内多个 prefix-old 就绪，自动 `batch=N`。

## 8. 可优化方向

### 8.1 协议与性能

1. **Ack 方向聚合**：目标片块末合并多条 ack，减少 S0→S1 反向消息（需保证 per-account FSM 与 PrevHash 顺序）
2. **自适应窗口**：按队列深度、pending delta 条数或带宽反馈调节 `DeltaAggregateWindowMs`（见 [期刊实验规划.md](./期刊实验规划.md) 实验六）
3. **π_delta / StorageRoot**：校验层增强，**不改变** 探针注入与 enqueue 逻辑
4. **打包优先级**：apply 后 promote 的 MigCtx new tx 提高 txpool 权重，缩短「SyncApplied 但尚无 new 上链」等待（自然流量与探针均受益）

### 8.2 实验与观测

1. 对比 `DeltaAggregateWindowMs ∈ {0, 50, 100, 200}` 的 send 条数、makespan、sync 延迟
2. 在 `sync.csv` 或 block 日志增加 **batch 大小分布** 统计脚本
3. 大账户数场景：验证单条 `SyncDeltaMsg` 体积上限与 TCP 分片策略

### 8.3 探针联调

- 缩短 `SyncProbePhaseBDelayMs` 可减小 send→tx2 块距，**不影响** 聚合正确性
- 验收聚合时关注 `batch=N` 与 apply/ack 条数仍为 N
