# 账户迁移策略对比（MVSS vs 基线）

本文说明本仓库**策略对比实验**中四种账户迁移方法的区别、控制变量设计、MVSS / MVSS-Delta 机制与代码入口。实验配置与 `-m` 参数见 [参数配置.md](./参数配置.md)。

---

## 一、实验要回答的问题

本文创新点在 **账户迁移过程本身**（迁移期如何处理 pending / 新到达交易、如何保持跨分片一致性），而不是在 **「如何把账户分到各分片」** 这一层。

因此对比实验应固定：

- 跨分片执行路径：**Relay**（Monoxide 式中继 + Merkle 证明，本仓库 `TryRelay` / `handleRelay`）；
- 账户重分配算法：例如 **CLPA**（或统一固定为 PageRank，见 `PorC`）；
- 触发时机、块大小、注入速率等链参数（见 `参数配置.md` §三）。

**唯一变化量**：迁移触发后，源/目标分片在 **TXmig1 → TXmig2 → Announce → 收尾** 阶段采用的 **账户迁移策略**。

---

## 二、控制变量逻辑

```text
固定：Relay 跨分片 + CLPA（或固定 PorC）重分配 + 相同负载/链参数
变化：迁移期内四种策略（SOTA-Lock / Fine-tuned-Lock / MVSS / MVSS-Delta）
```

| 层次 | 是否作为对比变量 | 说明 |
|------|------------------|------|
| 账户重分配（CLPA / PageRank 等） | **否，应固定** | 决定「谁迁到哪」；LB-Chain 的 LSTM+热点分配属于另一研究线 |
| 跨分片交易执行（Relay） | **否，应固定** | 四种策略共用同一 relay 栈 |
| 迁移期交易调度与状态同步 | **是** | 策略差异所在 |

### 与 LB-Chain 的关系

**LB-Chain**（Li et al., IEEE TPDS 2023）的主要贡献包括负载预测与账户分配算法、独立 Migration Transaction 等。本仓库用 **`-m SOTA-Lock`** 实现 Fine-tuned Lock 论文中的 **SOTA Lock** 全锁基线，**不单独实现 LB-Chain 协议**；论文表述上写 SOTA Lock（或注明「与 LB-Chain 类全锁语义对照」）。

---

## 三、四种策略在迁移过程中的区别

四种方法共用 **BlockEmulator 迁移流水线骨架**（`TXmig1` → `TXmig2` → `Announce` → `CaP`/pending 搬运），差异集中在 **迁移窗口内对交易的处置** 与 **Stage3 同步路径**。

### 3.1 总览表

| 维度 | SOTA-Lock | Fine-tuned-Lock | MVSS | MVSS-Delta |
|------|-----------|-----------------|------|------------|
| 代码 `-m` | `SOTA-Lock` | `Fine-tuned-Lock` | `MVSS` | `MVSS-Delta` |
| 核心思想 | 状态 + 全部关联交易锁住 | 只锁 Payer | 老/新分流 + 重定向 + TXsync | 同 MVSS + **增量** TXsyncDelta |
| 迁移期吞吐 | 低 | 中 | 高 | 高（sync 载荷更小） |
| Stage3 | 无 | 无 | 全量 `TXsync` | 增量 + PrevHash 链；失败 abort |
| 与论文 | FTL SOTA Lock | INFOCOM'24 半锁 | TrustCom MVSS | 期刊增量 |

### 3.2 SOTA-Lock（全锁基线）

1. `TXmig1`：`Lock_Acc[addr]=true`，关联交易进 `Locking_TX_Pools`。
2. sender/recipient 涉及迁出账户的 tx **暂停打包**；部分标记 `IsRelay`。
3. Announce 后 `CaP` 批量发往目标分片。

### 3.3 Fine-tuned-Lock（半锁基线）

1. 仅锁 **Payer**（sender 为迁出账户的非 relay tx）。
2. Payee 侧在规则允许下继续；Announce 前后分阶段 CaP。
3. 目标片 `TXmig2` 接管后继续处理积压。

### 3.4 MVSS（本文方法，Phase1）

1. **无整账户锁池**；老 tx（`RequestTime ≤ TXmig1_Time`）源片继续打包；新 tx **`mvssRedirectNewTx`** 至目标片（RedirectTag + nonce）。
2. 维护 `OrderList` / `LastCN`；`DetectInterleave` 发现 old-new-old 时 FSM 暂停部分老 tx，经 **`TXsync`** 桥接状态。
3. Announce 后可有 CaP 收尾，核心不依赖「锁死全部关联交易」。

### 3.5 MVSS-Delta（期刊增量，Phase2）

- **迁移骨架与 MVSS 相同**（分流、重定向、DetectInterleave 共用）；`IsMVSSDelta()` **仅分叉 Stage3**。
- 交错同步时发送 **`TXsyncDelta`**（`DeltaBalance` / `DeltaNonce` / `StartN`/`EndN` / `PrevHash`/`DeltaHash` / `Ack`），替代全量 `StateOld`/`StateNew`。
- 源片 State_ini 可按块末 **batch 聚合**（`DeltaAggregateWindowMs`，见 [聚合窗口.md](./聚合窗口.md)）。
- Delta 校验失败：**直接 abort**，不回退全量 `TXsync`。
- **未完整实现**：Ack 方向聚合、自适应滑动窗口 W、π_delta 证明等（见 [期刊实验规划.md](./期刊实验规划.md) 实验六说明）。

## 四、迁移时间线（概念对齐）

```text
时刻 ──────────────────────────────────────────────►

     [重分配结果下发]     [TXmig1]    [TXmig2/Ann]    [迁移完成]
  CLPA/Relay  ← 固定（非对比变量）

  SOTA      │████████ 全锁关联交易 ████████│  CaP 收尾   │
  Finetuned │████ Payer锁 ████│ Payee可走 │  CaP 收尾   │
  MVSS      │老tx执行│新tx重定向│ TXsync  │  目标片消化  │
  MVSS-Delta│  同上骨架          │ TXsyncDelta │ 更小 sync 载荷 │
```

## 六、MVSS 机制与代码实现

### 6.1 双时间戳与交错检测

| 语义 | 字段 | 用途 |
|------|------|------|
| 客户端逻辑顺序 | `ClientTimestamp` → `OrderList` | `DetectInterleave` 判定 old-new-old |
| 分片到达 / old-new 分界 | `RequestTime` vs `TXmig1_Time` | 分流、重定向 |

公开 CSV（如 300K）通常无独立 ClientTS；关闭探针时 ClientTS 回退为 RequestTime，**结构性难以触发 Stage3**（详见 [Sync探针注入.md](./Sync探针注入.md) §12）。

### 6.2 策略分叉

- `IsMVSS()`：进入 MVSS 迁移总线（分流 / 重定向 / TXmig 流水线）。
- `IsMVSSDelta()`：Stage3 走 `TXsyncDelta`；`IsMVSS()` 走 `TXsync`。
- 入口：`params/migration_strategy.go`；主逻辑：`pbft/mvss_sync.go`、`pbft/mvss_delta.go`、`account/mvss_ctx.go`。

### 6.3 Delta 协议对象与调用链

| 组件 | 文件 | 说明 |
|------|------|------|
| `TXsyncDelta` | `core/txsyncdelta.go` | 结构与 `CalcDeltaHash()` |
| 消息 | `pbft/cmd.go` | `cTXsyncDelta` / `SyncDeltaMsg` |
| 发送/接收 | `pbft/mvss_delta.go` | `TrySendTXsyncDelta`、`handleTXsyncDelta`、`mvssApplyDeltaSync`、`mvssOnDeltaAck`、`mvssAbortDelta` |
| 触发 | `pbft/mvss_sync.go` | `mvssTriggerSyncIfNeeded` → MVSS 或 Delta 分支 |
| 状态 | `account/mvss_ctx.go` | `LastDeltaHash`、`MigPendingDelta`、`MigAbortReason` |
| 出块应用 | `chain/blockchain.go` | `TakeMigPendingDelta` 应用增量 |
| 日志 | `pbft/sync_logger.go` | `S*_sync.csv`：`ts,event,mode,addr,start_n,end_n,ok,reason,bytes` |

Stage3 逐步时序与 mermaid 图见 [账户迁移时序.md](./账户迁移时序.md) §10。

### 6.4 预期指标差异

| 场景 | MVSS vs MVSS-Delta |
|------|---------------------|
| **未触发 sync** | 主流程几乎一致，RLT/延迟/TPS 差异很小 |
| **触发交错 sync** | Delta：**sync 字节↓**、消息载荷↓、同步阶段延迟有望↓ |
| **锁相关** | 由 MVSS 分流决定，Delta 不直接改变锁策略 |

Stage3 对比须 **开启 Sync 探针** 或可分离 ClientTS 的 benchmark；勿仅靠「增大并发」期待自然交错（见 [期刊实验规划.md](./期刊实验规划.md) 实验二）。

### 6.5 论文 vs 代码（简要）

| 论文能力 | 本仓库 |
|----------|--------|
| TXmig1/2、Announce、CaP、分流、RedirectTag+nonce | ✅ |
| DetectInterleave + TXsync | ✅ |
| TXsyncDelta + batch 聚合 MVP | ✅ |
| 滑动窗口 W、Ack 聚合、π_delta | ❌ 待扩展 |
| Stage3 可复现评估 | ✅ Sync 探针 + `S*_sync.csv` |

## 七、小结

| 问题 | 结论 |
|------|------|
| 控制变量 | 同 relay + 同 CLPA，只换 `-m` 策略 |
| 全锁 baseline | **`SOTA-Lock`**，非 LB-Chain 完整协议 |
| 本文方法 | **`MVSS`**；**`MVSS-Delta`** 为同策略 + 增量 Stage3 |
| Stage3 实验 | 主实验关探针；MVSS vs Delta 开探针微基准 |
